# 交接文档：lang2edit_agent(手势舞剪辑 agent)

> 面向接手者的一页总览。代码结构见各 `docs/模块N-*.md`，本文只记录
> 「怎么跑、在哪跑、踩过的坑、当前到哪了」。

## 项目是干什么的

一句话：自然语言驱动的视频剪辑 pipeline，六模块顺序协作，目标是
手势舞短视频（轮椅使用者可达性场景）：

```
utterance ─→ 模块一 gesture_intent   (EditingIntent/IntentPatch)
真实视频 ─→ 模块二 video_understanding (SemanticState + 事件/spatial)
          → 模块三 editing_planner    (LogicalEditingPlan, LLM creative + rules)
          → 模块四 asset_manager      (AssetRequest → 素材绑定/切换)
          → 模块五 edit_executor      (Revision 图 + Diff apply)
          → 模块六 session_feedback   (会话编排 + Undo/Redo,把前五者串成闭环)
```

六个模块全部落地，真实视频 e2e 已在超算走通（PR #9)。各模块设计文档在
`docs/模块一~六-*.md`；模块六是 `docs/模块六-反馈与持续修改.md`。

## 怎么跑

```bash

PYTHONDONTWRITEBYTECODE=1 /d/anaconda/python.exe -m pytest -q -p no:cacheprovider tests

# 超算(在 job 内)
srun --jobid=<JOB> --overlap -N1 -n1 --cpus-per-task=1 bash -lc '
  cd .../lang2edit_agent_gallant
  PYTHONDONTWRITEBYTECODE=1 .../envs/lang2edit/bin/python -m pytest -q -p no:cacheprovider tests'
```

## 坑位清单(都踩过，别再踩)

1. **模块一 json_object 静默回落**:qwen 会自造 `{raw,canonical,tags}` 结构，
   StrictModel `extra="forbid"` 拒收 → 静默走 rules_fallback。已用
   `llm_sanitize.py`（引导提示+白名单清洗）根治；看 `turns.jsonl` 的
   `parser_mode` 确认是否真走 llm。`json_schema` response_format 在该端点
   读超时，不可用——别试。
2. **能力门控**:planner `ToolCapabilityProfile` 默认 mask/tracking=False——
   replace_background + 轮椅保留会 pending_dependency。e2e 必须显式
   `FeedbackSession(tool_capabilities={...})` + executor
   `build_input(extra_artifacts=[mask artifact])` 注入掩码。
3. **恢复会话不要传 `vu=`**:FeedbackSession 自建 vu 才有 `_owns_vu=True`
   → `_require_state` 懒加载 `semantic_video_state.json`；显式传会
   `RuntimeError: call analyze_video() first`。
4. **replan 只喂 scoped intent**:`build_plan_patch` 构造 changed 需求 +
   目标落在 scope 的持久 op + music 需求（has_music 耦合）+ 全量约束。
   改这块前先想清楚 op 宿主回滚和 has_music 两个耦合点（patch.py 有注释）。
5. **queries_seen 累积必传**:`build_semantic_view(queries=…)` 不传会让
   已分析事件被判 not_analyzed → 假 dependency。
6. **EditView.object_type 是语义值**（如 "heart")不是枚举——bridge 必须经
   `source_requirement_ids[0] → requirement` 反查，不能直接当 ObjectType 用。
7. **materialize/apply_patch 原地改 plan**:undo 快照和落盘一律
   `model_dump` 深拷贝（session `_copy_plan`)。
8. **持久 op 语义**:scale/position/remove 落上后打 `adjusted_by:` 标记并进
   `source_requirement_ids`;replan 时宿主需求变更则 op 重新落到新项上。
9. **executor 只看 volume item 的 delta_db**:op 克隆路径写的 volume_offset
   是死参数（volume_adjust 走独立 volume item)。
10. **渲染 _bg_segments 必须按 dict 插入序**,sorted() 会按随机 uid 打乱。
11. **环境杂项**：计算节点**没有 ffmpeg**，抽帧/渲染用 PyAV;ssh 多层
    heredoc 引号极易翻车——写脚本文件 + scp，别嵌 heredoc;`tail` 管道会
    缓冲到结束才出输出，远端进度直接看 workspace 文件。

## 已知限制 & 建议后续

- **LLM 输出 token 是时延主因**（端点 ~25-35 tok/s):start 1321 completion
  tokens ≈ 40-58s。再压缩的方向是砍输出冗余项（tags/confidence/null 字段),
  即改 `GUIDED_SYSTEM_PROMPT` + 放宽白名单；reply 已是增量输出基本到顶。
- **"换一个"多实例歧义**：同 semantic_label 的多个背景并存时 switch
  fast-path 无法定位目标 → 回落 needs_clarification(travel6 reply6 实测)。
  后续可给 fast-path 补序号/时间词定位。
- **VU.load 丢 `_video_input`**：会话恢复后 on-demand 手部补跑不可用，
  只能靠已有 state；要修得在 load 时重建 video 句柄。
- `resolve_assets` 串行——量级太小（0.9s）不值得并行，别动。
- 模块三 creative LLM 仍每轮一次调用；若想再省，可给 rules_fallback 模式
  做旁路开关（utterance 命中纯参数类修改时跳过 creative)。
